# Upload/playback regression audit

These tests mount the existing `VideoPlayer` with synthetic video fixtures. They do not use real accounts, upload to Supabase, or change hosted media. Supabase HTTP requests are intercepted. Viewports are Chromium emulations, **not physical phones or tablets**.

Prerequisites: the project's JavaScript dependencies, FFmpeg/ffprobe with libx264, and Chromium. The repository's main Playwright configuration currently imports an unavailable Lovable package; this suite uses its own standalone configuration.

```sh
node tests/playback/prepare-fixtures.mjs
CHROMIUM_PATH=/usr/bin/chromium npx playwright test -c tests/playback/playwright.config.ts
```

Omit `CHROMIUM_PATH` when using Playwright's installed Chromium. The current repository has unrelated npm peer-dependency/lockfile problems; the audit environment used `npm install --legacy-peer-deps --package-lock=false --ignore-scripts` without changing the manifests.

The desktop dependency project runs the **production** browser encoder and saves its generated low/medium WebM files under `.media/`. An eight-second synthetic MP4 is padded beyond the existing 35 MiB threshold to exercise medium generation without a long encoding job. Padding changes the file size, not its duration or bitrate. FFprobe records the actual streams. The phone/tablet tests then play that generated low WebM and separately test controlled H.264 MP4 fixtures, fallback errors, quality controls, activation/deactivation, and HTTP range delivery at 1 Mbps with 150 ms latency. The quality-control high fixture is an explicitly supplied test source, not a high rendition generated by the production encoder.

Reports, screenshots, and media-event evidence are saved under `test-results/` in this directory by default. Override `PLAYBACK_RESULTS` and `PLAYBACK_ARTIFACTS` to save a comparison elsewhere. Generated media and reports are ignored by Git.

The broken baseline can be reproduced by using the original `src/components/VideoPlayer.tsx` with this suite: the missing-rendition case repeatedly switches between failed low/medium sources and never plays the available original. The fix remembers failed URLs until the video or explicit quality changes, tries each fallback once, and stops when every source fails. It changes no player markup or styles.

The constrained-network checks demonstrate a bandwidth limit, not a universal performance benchmark. Real-device Safari/Chrome, decoder support, memory pressure, PWA backgrounding, and actual user clips still require device testing.
